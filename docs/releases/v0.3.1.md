# CiruStrixLink 0.3.1

Version 0.3.1 makes the paired Launch page report runtime facts instead of a
hardcoded recipe and records the validated 256K DFlash configuration.

## Runtime state

- Each agent reads the managed launcher's DFlash depth and prefix-cache state.
- The console reports a setting as known only when both TP ranks agree.
- Missing settings remain unknown; conflicting DFlash settings are shown as a
  rank mismatch.
- Overview uses the managed DFlash setting when no manual display label is
  configured.
- Fast USB4 state is separate from speculative decoding and can report `in_use`
  while DFlash remains independently identified as k=5.

## Validated 256K recipe

- Context: 262,272 tokens.
- KV allocation: 8 GiB per rank.
- Topology: TP2, PP1, one rank on each machine.
- Speculation: DFlash2 k=5.
- Prefix cache: disabled until the disk tier has a byte quota and eviction.

The exact 65,680-token recovery prompt generated 256 new tokens at 15.12
output tokens/s. Matched controls measured 12.16 tokens/s at k=3 and 9.38
tokens/s target-only. HumanEval tasks 0–9 passed 10/10 at 26.10 weighted
generated tokens/s.

## Validation

- Complete Go test suite passed.
- `go vet` passed.
- Embedded JavaScript syntax and whitespace checks passed.
- Static Linux amd64 release build passed.
- Live read-only validation found both ranks loaded at 262,272 tokens, DFlash2
  k=5 on both, prefix cache disabled on both, and Fast USB4 `in_use`.
- The model was not stopped, restarted, or unloaded during release validation.
